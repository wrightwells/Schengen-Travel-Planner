# produstion v1.1

Version `1.1.0` brings the responsive household workspace, private proof documents,
password reset tooling and deployment documentation together in one build.

## What's included

- Home, History, Planner and More, with desktop navigation and mobile layouts.
- Independent traveller allowances, shared itinerary editing, live assessments,
  month/year calendars and timeline changes reviewed before saving.
- Authenticated proof upload/download/removal for confirmed history. A green tick
  marks entries with uploaded evidence and updates when documents change.
- File-based proof storage, including metadata, with private permissions, UUID
  paths, symlink checks, atomic writes and a volume mounted only into the API.
- PDF, JPEG and PNG proofs up to 10 MiB each, with up to 20 documents per entry.
- Optional `compose.proofs-host.yaml` for a prepared host directory instead of a
  Docker-managed volume, with migration instructions for existing uploads.
- `python -m app.reset_password` to choose a replacement household password,
  including `--password-stdin` for scripts. Reset clears lockouts and revokes sessions.
- A product README, real screenshots using fictional data, architecture diagrams,
  and linked user, API and deployment guides.

## Build outputs

- `ghcr.io/wrightwells/schengen-travel-planner-api:v1.1.0`
- `ghcr.io/wrightwells/schengen-travel-planner-web:v1.1.0`
- `schengen-web-v1.1.0.tar.gz` containing the compiled frontend.
- Release Compose configurations, the optional host-proof override, `.env.example`
  and the Tailscale Serve configuration.

Container images target Linux amd64. The frontend archive requires the API and
the Nginx proxy configuration; it is not a standalone application.

## Upgrade

Back up PostgreSQL and proof storage together, keep your existing environment file,
Compose project name and data volumes, and use the matching API and web image tags.
Run migrations before recreating the application services. Skip `app.bootstrap`
when your household account already exists. Never use `down -v` to upgrade.

The API runs as UID/GID `10001`, with a read-only root filesystem and private proof
storage at `/app/proofs`. For a host bind mount, prepare directories with ownership
mapped to that UID and mode `0700`; document files use `0600`. Copy existing proofs
before changing storage mounts, and retain the host override on future operations.

See the [installation guide](../../README.md#install) and
[host-storage migration instructions](../deployment.md#store-proofs-in-a-host-directory).

## Scope

This is a planning aid for a two-person household, not an immigration decision.
History completeness remains an explicit declaration. Scenario selections remain
browser-local. Uploaded documents are not malware-scanned or encrypted by the app.
Private Tailscale access controls, full restore verification and the remaining
release-hardening work are described in the development and deployment guides.
